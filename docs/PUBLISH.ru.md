# Публикация на GitHub

1. Открыть локальный клон `ThreadLeak/rzVault` в GitHub Desktop, проверить
   изменения, создать коммит и отправить его через Push origin. Историю форка
   сохранять; переписывать опубликованные теги не требуется.
2. Корень репозитория содержит `pom.xml`, `src`, `checkstyle.xml`, `.github`,
   `.mvn`, лицензии и wrapper. Соседние проекты, старую `Vault-master`, кэши,
   бэкапы и `target` в коммит не включать.
3. После отправки дождаться успешного workflow Build для Linux и Windows.
   Он проверяет стиль Java, совместимость API и поведение плагина. CodeFactor
   отдельно пересчитает оценку после получения нового коммита.
4. Создать тег `v1.0.2` и релиз к нему. Приложить устанавливаемый JAR, source JAR,
   полный ZIP исходников и SHA256SUMS из подготовленного комплекта релиза.
5. На сервер устанавливается только `rzVault-1.0.2.jar`. Должен оставаться один
   Vault-мост; `*-sources.jar` и ZIP — материалы разработчикам, не плагины.

Если имя или владелец репозитория отличаются, сначала обновить ссылки в pom.xml,
plugin.yml и README и собрать релиз заново. Исходники и бинарник релиза должны
соответствовать друг другу. Для следующего изменённого выпуска увеличить версию.
