# rzVault

[English](README.md) · [Лицензия](LICENSE) · [Изменения](CHANGELOG.md)

Небольшой мост классического Vault API для современных серверов Paper.
Создан **Raze / [ThreadLeak](https://github.com/ThreadLeak)** для HopeWorld и
подготовлен к общему использованию.

rzVault предоставляет API `net.milkbowl.vault.*`, показывает зарегистрированные
сервисы и содержит резервный обработчик Bukkit-прав. Балансы хранит отдельный
экономический плагин. rzVault не создаёт экономику и не заменяет LuckPerms.

## Что входит

- Полный классический VaultAPI 1.7, включая устаревшие методы, без relocation.
- `provides: [Vault]` для зависимостей современных плагинов.
- Диагностика Economy, Permission и Chat: выбранный провайдер, его плагин,
  приоритет и состояние. Chat — API метаданных, а не система сообщений игроков.
- SuperPerms с приоритетом Lowest и временными правами через свои attachments.
- Настраиваемые сообщения, HEX/обычные цвета и `%prefix%`, безопасный reload.

Старые адаптеры экономики/прав, телеметрия, проверка обновлений, базы данных и
периодические задачи в плагин не входят.

## Установка

Целевая платформа: **Paper 1.21.11, Java 21**. Другие версии не проверены.

1. Остановить сервер и сохранить прежний JAR моста и его настройки.
2. Установить `rzVault-1.0.2.jar` в `plugins/`.
3. Использовать только один мост: убрать прежний Vault, VaultUnlocked или rzVault.
   `*-sources.jar` на сервер не устанавливать.
4. Запустить сервер с плагинами-провайдерами и выполнить `/rzvault`.
5. Проверить реальные операции магазина/переводов с вашей связкой плагинов.

EssentialsX или rzEssentials могут сами зарегистрировать Economy. LuckPerms
обычно предоставляет Permission и Chat с приоритетом выше резервного SuperPerms.
Без Economy-провайдера rzVault запускается, но экономика у потребителей не появляется.
Данные денег и прав остаются у соответствующих провайдеров.

У старых плагинов, которым нужен исторический адаптер внутри Vault или внутренний
класс `net.milkbowl.vault.Vault`, совместимость не гарантируется. Расширения API
VaultUnlocked не реализованы. Неисправный выбранный провайдер не подменяется
исправным сервисом меньшего приоритета в диагностике.

## Команды и сообщения

`/rzvault` и `/vault-info` показывают сервисы; `/rzvault reload` применяет оформление.
Право — `vault.admin`, по умолчанию OP. Оно не позволяет управлять деньгами/группами.
При неверном конфиге сохраняется предыдущее рабочее оформление.

По умолчанию создаётся английский `config.yml`. Русский вариант:
[docs/config.ru.yml](docs/config.ru.yml). Существующие файлы сохраняются.
[Описание подстановок и поведения](docs/CONFIGURATION.md).

## Сборка

Нужен JDK 21. Официальный Maven Wrapper загрузит закреплённый Maven при первом
запуске. Для первой сборки нужен доступ к Maven Central и репозиторию Paper.
Исходники VaultAPI включены в проект; JitPack не требуется.

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress verify
```

Linux/macOS: `sh ./mvnw --batch-mode --no-transfer-progress verify`.

Результат: `target/rzVault-1.0.2.jar`; исходники — отдельный `*-sources.jar`.
Проверки GitHub Actions настроены для Linux и Windows; их выполнение на GitHub
произойдёт после загрузки репозитория. [Как опубликовать проект](docs/PUBLISH.ru.md) · [Выпуск релиза](docs/RELEASING.md).

Код распространяется по **LGPL-3.0-or-later**. Авторство MilkBowl / VaultAPI и
лицензии сохранены; [NOTICE.md](NOTICE.md) содержит точную исходную ревизию.
